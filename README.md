# Shijian Agent distribution

Public installation scripts and checksum-pinned Linux amd64/systemd and Docker amd64 packages.
Generate the installation command in your Shijian server management page. It includes your private node configuration: treat it as a credential and never post it here.

The short command uses `curl -fsSL PINNED_INSTALLER_URL | bash -s -- --endpoint HTTPS_ORIGIN --server-id NODE_ID --token REPORT_TOKEN`, with optional `--interfaces eth0,eth1`, `--docker` and `--github-proxy https://gh-proxy.org/`. When this proxy is selected in the control panel, both the pinned installer URL and package URL are prefixed with `https://gh-proxy.org/`; configuration and credentials are only used locally and are never sent to the proxy. The installer embeds frozen package versions, SHA256 and Docker image ID. Installation requirements and reminders are printed on the target machine; configuration is written with mode 0600 and is never printed or sent to GitHub. The earlier JSON-via-stdin interface remains available with explicit package arguments. Offline commands use the exact same installer with --package-file and --config-file, without package downloads.

The command downloads the installer over HTTPS at a fixed commit. Its SHA256 is checked at publication and recorded in the control panel distribution manifest; the short command does not perform a separate pre-execution script hash check. The installer verifies the downloaded package SHA256 against its embedded frozen release metadata. Packages live in `agent-VERSION` Releases. There is no automatic update. The same command installs or upgrades an existing standard deployment for the same endpoint, node and deployment type. It verifies the package before stopping anything, backs up the old program/container metadata, configuration and stopped latest state, then atomically replaces the program or recreates the container. Startup failure restores the old deployment and configuration while preserving the latest queue, never restoring a stale state backup. Native service definitions and Docker restart policies are retained. Omitted --interfaces preserves the existing local selection. A command targeting a different node or endpoint rebinds the installation after backing up configuration and isolating the entire previous state directory. The new identity receives an independent session/outbox; old measurements are never replayed as new-node data. Failed rebind restores the previous identity and state directory and separately archives the failed new identity state with its requested configuration. Mixed/foreign deployments remain rejected before stopping the existing agent. After uninstalling, retained standard configuration and state can also be reused automatically for the same endpoint and node. The installer verifies identity and checks the state lock, backs up the old configuration, atomically installs the supplied credentials, and preserves the latest state/queue. Empty retained directories are also accepted. Ambiguous configuration, a different identity, unsafe file types or an occupied state lock are rejected without deleting data. State recovery requires flock (util-linux).

After installation, the script prints status, logs, temporary stop/start, restart, automatic startup and uninstall commands for the selected platform, and saves the same instructions to `/etc/shijian-probe/OPERATIONS.txt`. Uninstall instructions preserve configuration and state and remind the user to revoke the control panel token.

Missing dependencies, network errors, integrity failures and service startup errors stop installation. Temporary files are cleaned; installed configuration and state remain available for diagnosis. Service startup alone does not confirm delivery to the control panel.

Package-specific license and third-party notices are included in each release package. This repository contains no per-node configuration, credentials, runtime state, or private application source.
